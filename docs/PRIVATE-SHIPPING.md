# Private Files shipping candidate

Added 2026-10-03. This candidate implements personal-first private shipping; it is not production-qualified or deployed.

## Distribution and authority

The browser package contains the shared shipping coordinator, AES-GCM worker, immutable transport archive, durable encrypted operation journal and source-retention hooks. Views, sidebar navigation, branding, homepages, CSP and application service-worker policies remain consumer-owned. The index and gateway have a separate Node 24.18.0 operator package with durable SQLite metadata. See ../services/README.md in corresponding source; the server runtime is not bundled into webpages. Neither package contains S3 credentials, service keys or a bundled s3d executable.

The index is the private discovery root and sole accepted-submission head. It verifies existing controller signatures and signer-bound Castalia v3 base membership; a v4 community proof does not qualify. Personal creation resolves to one accepted identity and initial workspace. Organization creation must use the real owner's signed Organization registration and accepted canonical binding. The Zenith name alone cannot reserve or activate its destination. In this first release, organization shipping is restricted to the explicitly configured canonical Zenith binding; both destination discovery and server admission check its namespace and registration genesis. General organization destinations remain outside this release. Destination discovery exposes submit and update-own authority separately: update-only grants permit revisions of an existing uploader-owned submission but never new submissions. Organization grant `maxBytes` is a per-revision ciphertext ceiling; owner connection and gateway account budgets are separate cumulative reservations. Controllers authorize bounded upload admission; namespace placement, payment and membership never authorize reading another uploader's data. Prior owner-visible history and withdrawal remain available after upload revocation.

Both sites pin the index origin/key and the configured gateway origin/key. This permits exact CSP network origins. Recovery discovers saved account metadata from the authenticated index, but the deployment must already trust that gateway; an arbitrary URL in discovery never changes the trusted endpoint. Each origin authenticates independently. Matching namespace IDs do not synchronize OPFS or IndexedDB.

## Shipping transaction

1. Select a committed local root and, optionally, one file. Capture under its existing mutation lock and persist a source pin. Workspace transports retain original object bytes and namespace values. A file transport contains only the selected file bytes and encrypted restoration metadata.
2. Disclose the configured provider/account, capacity allowance and linked retention/renewal terms. The operator account must authorize the uploader. No purchase and no fixed retention promise are performed.
3. Generate and wrap a fresh revision key through custody; encrypt in a dedicated worker. Persist the same ciphertext, nonce, binding and operation journal atomically before network transmission. Cancellation before that checkpoint releases the pin; resumable or uncertain operations retain it. An operation lock spans preparation through the first durable journal write. A later explicit connection can recover orphaned preparation pins only after obtaining that lock and confirming that no operation was persisted. Verified Shipped state, pin release and redundant ciphertext removal commit atomically.
4. Obtain a bounded index intent, upload exact ciphertext parts through the gateway, and reconcile multipart status after interruptions. The gateway verifies the official s3d release, serializes its verification batch, flushes and requires explicit zero pending/unpinned counts. The official binary and a real host still require operator qualification.
5. Retrieve the exact immutable version using fresh gateway reads. Verify ciphertext size/hash, decrypt through newly approved custody access, then validate the full file or snapshot transport using actual WASM. Local upload buffers cannot satisfy this check.
6. Recheck admission and previous head in one SQLite index transaction. A verified acceptance receipt permits `Shipped`; retained local source remains available. Lost responses reconcile the stable operation ID. Conflicts keep both immutable remote revisions and do not silently retry against a new head.

The UI states are Local only, Shipping, Shipped, Local changes and Failed. Shipping includes paused/resumable and checking-completion details. Local edits never mutate the selected shipment; a changed local root is shown as Local changes during or after shipping, while the underlying shipment progress and resume state are retained. Terminal authority/integrity errors need explicit resolution. Worker loss, cancellation or service loss never becomes successful publication.

## Recovery and local storage

Existing legacy database/catalog/OPFS paths and lock names are unchanged. A separate versioned shipping database stores ciphertext/journals and scoped source pins. Pins participate in bounded reclamation under the same workspace lock. Every worker keeps its immutable local binding. Unknown journal schemas fail closed. Cross-workspace deduplication is not introduced.

Remote recovery authenticates the same recovered Member Key, discovers accepted private entries, verifies index/storage receipts and unwraps the remote envelope. There is no additional recovery secret. It offers an explicit local import with an expected-head check, including an absent legacy head. A workspace snapshot can only retain its original namespace; copying into another namespace is a separate deliberate operation. A failed import preserves existing catalog heads. The original local copy is not removed by shipping or recovery.

Withdrawal tombstones namespace placement while preserving owner-visible receipts, keys and bytes. It does not promise host deletion; provider unpin/deletion and host shard retention are separate. Wallet recovery restores decryption authority, not missing index/gateway/Sia metadata. Operator backup and restore are independently tested.

## Qualification and notices

Synthetic Node/SQLite/HTTP tests and actual-WASM archive tests are review evidence, not real-host acceptance. Production qualification still requires complete pinned consumer artifacts, real issuer/controller inputs, permissions for inherited material, funded authorized Sia infrastructure, a user-selected private archive and authorized immutable HTTPS staging with the identical artifact digest. No merge, registry release or deployment is authorized by these checks.

The new work retains AGPL-3.0-or-later; existing unresolved inherited-source permissions remain blockers. Third-party terms and historical notices are retained. New server-side remote execution adds an actual network-interaction distribution boundary for review under LICENSE section 13; the operator must provide the applicable Corresponding Source opportunity. The browser source manifest, service source manifest, locks and reproducible build instructions identify the delivered candidates, but do not themselves establish legal clearance. Native bridge, FUSE, sharing, public publication, unsupported Dregg capabilities, pay-at-push and a self-operated indexer remain unavailable.
